How we validated model wiring by overfitting on 100 examples

What is a Smoke Test?

Before training on 360K examples for real, answer one question:
Is the model wired correctly?

The Method

  • Take just 100 examples
  • Train for 50 epochs
  • Evaluate on the same 100 examples
  • Can the model memorize them?

The Logic

  • If it can't overfit 100 examples → something is broken
  • If it can overfit → architecture works, move to real training

Key asymmetry: DeBERTa already knows language. The CRF head knows nothing.

Why CRF?

A standard classifier predicts each token independently. A CRF predicts the entire sequence jointly.

Without CRF (Independent)

Token: John Smith lives in Pred: B-PER B-LOC O B-PER

Each token predicted in isolation. "Smith" mislabeled because the model doesn't see it follows "John".

With CRF (Sequential)

Token: John Smith lives in Pred: B-PER I-PER O O

CRF learns: B-PERSON → I-PERSON is likely, B-PERSON → B-LOCATION is not.

Important: CRF loss (negative log-likelihood) is sequence-level, not per-token. Values of 1–50 are normal. This is not comparable to cross-entropy.

Diagnosis: The All-O Trap

In PII data, ~85-90% of tokens are O (not an entity). Predicting all-O is a comfortable local minimum.

What the model learned

Input: "Contact John Smith at john@acme.com for details" Pred: O O O O O O O Gold: O B-PER I-PER O B-EMAIL O O

Loss still decreases by getting O predictions more confident, without ever predicting entities.

Why it's stuck

  • Backbone representations destroyed by high LR in early epochs
  • CRF transition matrix stuck at uniform — no strong B → I preferences
  • All-O reduces loss without risk of wrong entity predictions
  • Without good backbone features, CRF has no signal to learn from

The Fix: Differential Learning Rates

Preserve what's good. Let new parts learn fast.

The Inflection Point: Epoch 11

For 10 epochs, metrics were identical to Run 1: all zero. But the loss told a different story.

What was happening internally

  • CRF transition matrix gradually learning that B-PER → I-PER is valid
  • Backbone features being gently tuned for PII context
  • Emission scores for entity tags slowly increasing
  • At epoch 11, scores finally cross the threshold to beat the all-O path

Why metrics are binary

Seqeval requires exact entity boundary matches.

Gold: [B-PER] [I-PER] [I-PER] Pred: [B-PER] [I-PER] Score: 0.0 ← close but no credit

Metrics jump from 0 to non-zero when the CRF finally gets entire entity spans right.

How to Read These Metrics

Overall Metrics

F1 = 0.992 — Harmonic mean of precision and recall. The single best number for "how good is this model?"
Precision = 0.985 — Of all entities the model predicted, 98.5% were correct. (Low FP)
Recall = 1.000 — Of all real entities in the data, 100% were found. (Zero FN)
Eval Loss = 0.288 — CRF sequence-level NLL. The model assigns ~75% probability to the exact correct tag sequence.

Tier Recall (PII Severity)

Tier 1 = 1.000 — Direct identifiers (SSN, passport, credit card). Miss = immediate breach.
Tier 2 = 1.000 — Strong identifiers (email, phone, DOB). Can identify individuals.
Tier 3 = 1.000 — Contextual PII (name, location, organization). Identifying in combination.
Tier 4 = 1.000 — Sensitive attributes (gender, religion, political). Protected categories.

In production, Tier 1 recall is the most critical — missing a credit card number is worse than missing a first name.

How BIO Tagging Works

Every token gets one of 163 labels: O (outside), B-TYPE (begin entity), or I-TYPE (inside entity).

Example: "Contact Kattie at john@acme.com"
TokenTagMeaning
ContactONot an entity
KatB-PERSONStart of a person name
##tieI-PERSONContinuation of that name ("Kattie")
atONot an entity
johnB-EMAILStart of an email address
@acmeI-EMAILContinuation of email
.comI-EMAILContinuation of email

Key: The B- prefix marks where an entity starts. The I- prefix marks every subsequent token of that same entity. The CRF ensures I-EMAIL can only follow B-EMAIL or another I-EMAIL — never appear out of nowhere.

Why this matters

  • Precision = 0.985 means only 1.5% of predictions are false positives
  • In production, false positives cause unnecessary redaction of normal text
  • The model isn't just pattern-matching — it understands context
  • Example 2 has "Omer" as a person, but the model doesn't hallucinate entities in Examples 1 and 4 where there are none

Recall 1.000 + Precision 0.985 means: find everything, with almost no false alarms.
